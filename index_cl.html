Core Contribution

PhD Thesis: Cross-Layer GPU Information Leakage

My thesis examines information leakage across three abstraction layers—microarchitectural resources, interconnect fabrics (NVLink), and application-level LLM inference—demonstrating that no single mitigation eliminates all channels. The unifying finding is that GPU systems consistently expose measurable side-channel signals regardless of the abstraction level at which the attacker observes.

SideLink: Exposing NVLink to Covert and Side-Channel Attacks

Issa Baddour, Somitra Kumar Sanadhya, Dip Sankar Banerjee

Journal of Hardware and Systems Security (Special Issue)
DOI →

NVLink is a high-bandwidth interconnect in NVIDIA GPU systems that has become essential for AI workloads in data centers. Despite its high bandwidth, we show that NVLink exhibits measurable contention characteristics that enable both covert and side-channel attacks. We evaluate SideLink across NVIDIA's Hopper (H200), Ampere (A100), and Volta (V100) architectures, achieving covert channel bandwidths of 8.29 Kbps, 9.90 Kbps, and 6.33 Kbps respectively with negligible error rates. We further implement an application fingerprinting side-channel, achieving a maximum accuracy of 96.2% across 25 dual-GPU applications. We propose and evaluate temporal and spatial partitioning countermeasures for NVLink, analyzing their effectiveness and performance overhead.

An Improved Micro-Architectural Covert-Channel Attack on GPUs

Issa Baddour, Somitra Kumar Sanadhya, Dip Sankar Banerjee

Journal of Hardware and Systems Security
DOI →

We address two major challenges in GPU covert-channel research: improving bandwidth and evading detection. We present an enhanced mechanism that extends binary contention-based communication to a four-level signaling scheme, achieving error-free communication at over 44 Mbps on a single GPU and over 340 Mbps across 8 GPUs on an NVIDIA DGX A100 system. We also systematically construct covert channels using every available function on the special function units (SFUs) and introduce behavioral randomization by dynamically combining these configurations. This randomized strategy achieves up to 38 Mbps (single GPU) and 274 Mbps (8 GPUs) with BER under 10%, and significantly reduces ML-based detectability compared to traditional approaches.

Side-Channel Leakage in Large Language Model Inference on GPUs

Issa Baddour, Somitra Kumar Sanadhya, Dip Sankar Banerjee

Under Review

We study whether CUDA runtime activity, kernel execution patterns, and GPU telemetry can be used to infer hidden properties of LLM inference. Collecting execution traces from seven LLMs (OPT, Mistral, Phi-2, Qwen2, TinyLlama, Falcon, and one additional model) under realistic conditions—allowing variable input lengths, stochastic decoding, and natural termination—we evaluate two tasks: (i) prompt-family inference, recovering high-level semantic categories of inputs; and (ii) model fingerprinting, identifying the executing model. Model fingerprinting reaches up to 99.94% accuracy with combined features and exceeds 97% using individual feature groups. These results reveal an asymmetry between prompt- and model-level leakage: model-level execution signatures remain stable and highly distinctive, indicating persistent GPU-side fingerprints that are difficult to obscure under realistic inference conditions.

Execution-Level Covert Channels on GPUs

Problem: Can co-resident GPU processes communicate covertly at practical bandwidths while evading ML-based detection?

Approach: We reverse-engineered warp and block scheduling behavior on the NVIDIA A100 and extended binary contention-based channels to a four-level signaling scheme. To evade detection, we systematically exploited every function on the GPU's Special Function Units (SFUs) and introduced behavioral randomization—dynamically combining SFU function configurations within a single channel to obscure consistent usage patterns.

Threat model: Multi-tenant cloud GPU environments, e.g., shared AI inference nodes where attacker and victim co-reside on the same physical GPU.

hub Project 2

SideLink: NVLink Side-Channel & Covert-Channel Attacks

Problem: NVLink is a critical high-bandwidth interconnect in multi-GPU AI systems. Does it introduce new attack surfaces? Can an unprivileged process exploit NVLink contention to communicate covertly or fingerprint co-resident workloads?

Approach: We observed that NVLink exhibits measurable contention characteristics accessible via performance counters. We built a covert channel by modulating NVLink traffic from a sender process while a receiver monitors latency—tested across three GPU generations (V100, A100, H200). For the side channel, we collected NVLink latency traces from 25 dual-GPU applications including hashing and cryptomining workloads, then trained ML classifiers to fingerprint applications without any direct memory access.

Countermeasures: We propose and evaluate temporal and spatial partitioning strategies for NVLink, analyzing their effectiveness and performance overhead in cloud environments.

psychology Project 3

Side-Channel Leakage in LLM Inference on GPUs

Problem: LLMs are increasingly deployed on shared GPU infrastructure. Can an unprivileged observer—sharing a GPU with an LLM inference server—infer the model being executed or the semantic category of user prompts, without any direct memory access?

Approach: We collected CUDA runtime activity, kernel execution patterns, and GPU telemetry traces from seven LLMs (OPT, Mistral, Phi-2, Qwen2, TinyLlama, Falcon) under realistic conditions: variable input lengths, stochastic decoding, and natural termination. Previous work had only studied deterministic decoding, which does not reflect real deployments. We evaluated two tasks: prompt-family inference and model fingerprinting, using multiple ML classifiers and feature groups.

Key finding: An asymmetry exists between prompt- and model-level leakage. Model-level execution signatures are stable and highly distinctive—difficult to obscure even under stochastic decoding—while prompt-level signals are more affected by runtime variability.
